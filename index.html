Introduction to the 8-Puzzle Problem

The 8-Puzzle is a classic artificial intelligence problem consisting of a 3×3 grid containing eight numbered tiles and one empty space. The objective is to move the tiles by sliding them into the empty space until the board reaches a specified goal configuration.

Each arrangement of the puzzle represents a state, while moving a tile into the empty space produces a new state. The complete set of possible arrangements forms a state space. A search algorithm explores this state space to find a sequence of valid moves from the initial state to the goal state.

How the Puzzle Works

The empty space can move up, down, left, or right, provided that the corresponding position exists on the board. Each valid movement generates a successor state. Starting from the initial configuration, a search algorithm repeatedly evaluates these states until the goal configuration is reached.

Initial State

The starting arrangement of the eight tiles and the empty space.

Successor States

New puzzle configurations produced by valid movements of the empty space.

Goal State

The target configuration that the search algorithm attempts to reach.

8-Puzzle as a Search Problem

The 8-Puzzle can be modeled as a state-space search problem. The initial configuration acts as the starting state, the desired configuration is the goal state, and each legal tile movement represents an action that transitions the puzzle to another state.

In this application, Uniform Cost Search (UCS) is used to explore the state space. UCS expands the node with the lowest accumulated path cost, allowing the application to demonstrate how an uninformed search algorithm systematically explores possible solutions.

Algorithm Information & Theory

Detailed educational overview of search algorithms, focusing on Uniform Cost Search mechanics on the 8-puzzle.

Uniform Cost Search (UCS) — Comprehensive Deep Dive Assigned Implementation

Uniform Cost Search (UCS) is an uninformed graph search algorithm that explores the state space systematically in order of increasing cumulative path cost from the start state, denoted as g(n). While Breadth-First Search (BFS) expands nodes level by level (assuming equal cost for all transitions), UCS generalizes this to arbitrary non-negative step costs, guaranteeing that when a goal node is selected for expansion, the optimal lowest-cost path has been found.

1. State-Space Representation

The 8-puzzle is modeled as a graph where each node is a permutation of 9 tiles (0–8). Moves consist of sliding adjacent tiles into the empty space (0).

2. Priority Queue Frontier

The frontier (Open List) is maintained as a Min-Heap keyed on g(n). Ties are broken in FIFO order to preserve deterministic behavior.

3. Goal Testing on Expansion

Crucial rule: UCS tests for the goal upon selection/expansion from the queue, not upon node generation. This guarantees path optimality.

4. Explored Set & Duplicate Elimination

A Closed List (Map) tracks visited states. If a newly generated successor matches an explored state with lower or equal cost, it is discarded.

Algorithm Execution Walkthrough
  1. Initialize the Frontier with the root node: state = initial, parent = null, cost g(root) = 0.
  2. If the Frontier is empty, terminate with failure (no solution exists).
  3. Extract the node n with minimum g(n) from the Frontier.
  4. If state(n) == goal, reconstruct the optimal path using parent pointers and return success.
  5. Add state(n) to the Explored set.
  6. For each valid move from state(n), generate successor child node with g(child) = g(n) + stepCost.
  7. If the child is neither in Explored nor Frontier with lower cost, insert it into the Frontier.
  8. Repeat from step 2.
UCS Complexity & Performance on the 8-Puzzle
Time Complexity: O(b1 + ⌊C*/ε⌋), where b ≈ 2.67 (effective branching factor), C* is optimal cost, and ε is minimum step cost.
Space Complexity: O(b1 + ⌊C*/ε⌋), storing all nodes in both the frontier heap and explored map.
Overview of Other State-Space Search Algorithms

Working Principle: Expands nodes in strict shallowest-first order using a First-In-First-Out (FIFO) queue.

Advantages: Guaranteed to find the shallowest goal state; complete on finite graphs; optimal when all action costs are identical.

Limitations: High exponential memory consumption O(bd); stores the entire frontier in RAM, making it impractical for deep 8-puzzle configurations.

Complexity: Time: O(bd) | Space: O(bd) | Complete: Yes | Optimal: Yes (unit-cost).

Working Principle: Expands the deepest node in the current frontier using a Last-In-First-Out (LIFO) stack.

Advantages: Extremely modest linear memory consumption O(b·m), requiring only storing the current active search path.

Limitations: Incomplete in infinite or cyclic state spaces; can get trapped in repetitive cycles; not optimal (often finds needlessly long solution paths).

Complexity: Time: O(bm) | Space: O(b·m) | Complete: No | Optimal: No.

Working Principle: Executes Depth-First Search with a predetermined depth cutoff limit l. Nodes at depth l are treated as having no successors.

Advantages: Solves the infinite path issue of pure DFS while maintaining low linear memory requirements O(b·l).

Limitations: Incomplete if the shallowest goal is deeper than l; not optimal if l > d.

Complexity: Time: O(bl) | Space: O(b·l) | Complete: No (if d > l) | Optimal: No.

Working Principle: Repeatedly runs Depth-Limited Search, incrementing the depth bound l = 0, 1, 2, ... until a goal is found.

Advantages: Combines the optimality and completeness of BFS with the linear space efficiency of DFS.

Limitations: Repeated generation of upper-level tree nodes (though overhead is small because the bottom level dominates in high branching factors).

Complexity: Time: O(bd) | Space: O(b·d) | Complete: Yes | Optimal: Yes (unit-cost).

Working Principle: Uses a heuristic function h(n) (e.g., Manhattan distance or misplaced tiles) to expand the node that appears closest to the goal.

Advantages: Highly efficient and fast when the heuristic is accurate, rushing toward the goal with fewer expansions.

Limitations: Neither complete nor optimal; prone to wandering down false trails if misleading local heuristics appear attractive.

Complexity: Time: O(bm) worst-case | Space: O(bm) | Complete: No | Optimal: No.

Working Principle: Evaluates nodes by combining backward path cost g(n) with forward estimated cost h(n): f(n) = g(n) + h(n).

Advantages: Both complete and optimal when using an admissible heuristic (e.g., Manhattan distance for 8-puzzle); optimally efficient among all heuristic search algorithms.

Limitations: Space-bound: retains all generated nodes in memory, which can exhaust RAM on complex puzzle instances without memory-bounded variants (e.g. SMA* or IDA*).

Complexity: Time: O(bd) worst-case | Space: O(bd) | Complete: Yes | Optimal: Yes.
